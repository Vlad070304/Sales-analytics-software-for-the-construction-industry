# Дані BuildSales Insight: походження та практичні джерела

## Демонстраційні дані в програмі

Під час першого запуску програма створює локальну SQLite-базу з **синтетичним, відтворюваним набором даних**. Він генерується функцією `seed` у `app/database.py` і не містить реальних клієнтів, контрагентів або персональних даних.

Набір містить чотири типи будівельних матеріалів, щомісячні продажі за 2025–2026 роки, чотири умовні клієнти та три умовних менеджери. Для перевірки аналітичних алгоритмів у нього штучно закладено:

- сезонний множник від 0,60 до 1,30, зростання в активний будівельний сезон;
- помірний місячний тренд 1,8%;
- збільшення обсягів 2026 року на 10% і цін на 4%;
- різні залишки та строки постачання матеріалів.

Ці параметри потрібні лише для демонстрації прогнозу, CPRI, UPR та SADI. Їх не можна подавати як фактичні ринкові результати підприємства.

## Основне джерело для реального впровадження

Базою для аналітики мають бути первинні дані підприємства:

1. CRM або журнал замовлень — дата угоди, клієнт, менеджер, матеріал, кількість і ціна.
2. ERP чи бухгалтерська система — проведені накладні, повернення, собівартість та статус оплати.
3. Складська/WMS-система — поточний залишок, резерви, мінімальний запас і одиниця виміру.
4. Відділ закупівель — фактичний строк постачання, ціни постачальника, мінімальна партія.
5. Інтернет-магазин або POS — вивантаження підтверджених продажів за період.

Для початку достатньо CSV із шістьма колонками: `sold_at`, `material`, `manager`, `customer`, `quantity`, `unit_price`. У програмі натисніть **«Імпортувати CSV» → «Так»**, щоб створити порожній шаблон з цими заголовками. Назва матеріалу у файлі має вже існувати у довіднику «Матеріали».

Перед передаванням файлу варто вилучити зайві персональні дані. Для експорту з програми доступне знеособлення клієнтів і менеджерів; для імпорту слід використовувати псевдоніми або коди контрагентів, якщо реальні імена не потрібні для мети аналізу.

## Зовнішні джерела для збагачення аналітики

Зовнішні набори не замінюють історію власних продажів, проте можуть бути додатковими індикаторами попиту після окремої перевірки якості.

| Джерело | Що можна взяти | Як застосовувати |
| --- | --- | --- |
| [Prozorro](https://prozorro.gov.ua/) та [відкрите API](https://prozorro.gov.ua/openprocurement) | тендери, плани та договори за категоріями будівництва або кодами CPV | агрегувати кількість чи очікувану вартість тендерів за місяцем/регіоном як зовнішній індикатор майбутнього попиту; це не є фактичними продажами компанії |
| [Єдина державна електронна система у сфері будівництва: відкритий набір](https://data.gov.ua/en/dataset/0c352c5f-786b-4407-9c3d-49cddd63452e) | декларативні документи та активність у будівельній сфері | обчислювати кількість подій за місяцем або регіоном як індикатор активності будівельного ринку |
| [Держстат: статистика будівництва](https://www.ukrstat.gov.ua/druk/publicat/kat_u/2023/zb/11/year_22_e.pdf) | індекси й обсяги будівельної продукції, введення житла в експлуатацію | використовувати для макроринкового контексту, порівняння динаміки та формування зовнішніх факторів |

Для будь-якого зовнішнього джерела потрібно зберегти дату отримання, фільтр відбору, посилання, регіон і спосіб агрегування. Це зробить експеримент у магістерській роботі відтворюваним. У відкритих даних Prozorro необхідно вказувати джерело, як того вимагають умови повторного використання.

## Рекомендований мінімальний набір для дослідження

Для перевірки гіпотез достатньо 12–24 місяців продажів для кожного матеріалу, актуальних залишків і строків постачання. Дані варто розділити хронологічно: ранні місяці — для налаштування моделі, останні — для незалежної перевірки MAE, дефіцитів та надлишкового запасу.
